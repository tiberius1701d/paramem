## Scope

Categories to scrub: {scrub_categories}

Placeholder a value ONLY if it is an instance of one of these categories. Everything else — city, organization, product, or any category not listed — stays verbatim, even if it is a proper noun or an identifying name of some kind.

Doubt can come from two different questions. They are not the same question, and they resolve in opposite directions:
- **Membership: is this category listed above at all?** A lookup, not a judgment — e.g. checking whether "city" appears in the category list. When THIS is what you're unsure about, leave the value verbatim.
- **Instance: the category IS listed — is this particular value really an instance of it?** e.g. "phone number" is listed — is `+49 151 2345` a phone number or an order reference? When THIS is what you're unsure about, placeholder the value. Over-scrubbing here costs nothing lasting — it becomes an opaque token restored locally when the reply comes back. Under-scrubbing sends real PII to the cloud, and that can never be undone.

## Placeholder shape contract

Each placeholder is `<Prefix>_<N>` where:
- `Prefix` is a PascalCase noun naming the value's category. Common prefixes are `Person`, `Phone`, `Email`, `Address`, `Profile`, but you may use any type-appropriate PascalCase prefix when one of these doesn't fit the listed categories.
- `N` is a positive integer. Allocate the smallest free index per prefix in order of first appearance (`Person_1` before `Person_2`).
- Each real value must map to a UNIQUE placeholder. No two real values share the same placeholder.

## Rules

- **`speaker{{N}}` (e.g. `speaker0`) is already anonymous — leave it VERBATIM.** It is the extractor's own anonymous handle for the person talking, not an identifying name. NEVER add a `speaker{{N}} → Person_N` entry to `mapping`, and never treat `speaker{{N}}` as a value to anonymize.
- **Totality:** once you HAVE decided a value is in scope, you MUST add its `real_value → placeholder` entry to `mapping` in the same response — every placeholder decision you make must be backed by a mapping entry, with no exceptions.
- Mapping direction is `real_value → placeholder`: the real value is the JSON KEY, the placeholder is the JSON VALUE.
- Use the SAME placeholder for every occurrence of a value across the facts.
- The facts below are the material to work from. Common nouns are NEVER added to the mapping, even if the extractor capitalised them. "Dog", "Partner", "Friend", "Assistant", "User" are common nouns — they are never PII regardless of scope.
- Numeric values, dates, and currencies that do not belong to one of the listed categories stay verbatim. A phone number IS in scope when "phone number" is listed — mint a placeholder for it like any other in-scope value.
